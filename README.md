## 🧭 How I work

```mermaid
flowchart LR
    A[Understand the problem] --> B[Agree scope and price]
    B --> C[Build in small steps]
    C --> D[Test it properly]
    D --> E[Deploy and hand over]
    E --> F[Stay around for changes]
```

| | Principle | In practice |
|---|---|---|
| 🔍 | **Look before quoting** | I find out what is actually going on first, so the price and scope do not move halfway through. |
| 💬 | **Plain English updates** | You talk to me directly and get a clear update at each stage. |
| ✅ | **Test what matters** | Search quality, payments and anything that loses data get real tests. |
| 🧱 | **Keep it simple** | The simplest structure that does the job, so the next developer can follow it. |
| 🤝 | **Stay after launch** | Things change once real people use the product, and I am still around for that. |
